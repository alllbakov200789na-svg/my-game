# JUJUTSU: CURSED SURVIVAL — 0.1.0 alpha

Создано 24 октября 2026 года. Файловая реализация игры для Roblox Studio: 5 режимов, 3 процедурные карты, лобби, 26 боевых действий, серверные сервисы, клиентский интерфейс и прогрессия.

**Это непроверенная в Roblox Engine alpha, а не подтверждённый готовый релиз.** Подключение Studio MCP вернуло пустой список; существующего проекта не было. Синтаксис и автономные тесты проверены, но критерий полного мультиплеерного цикла из задания пока не подтверждён.

## Открыть игру

1. Распакуйте весь архив в отдельную папку.
2. В Roblox Studio выберите **File → Open from File** и откройте `JujutsuCursedSurvival.rbxlx` из этой папки. Файл уже содержит исходники, лобби и все карты; импорт через Command Bar не нужен.
3. Нажмите **Play**. После загрузки R15-шаблона и входа игрока начинаются перерыв 20 секунд, выбор 5 секунд и вступление 5 секунд. Один игрок автоматически играет Survival за Астру с NPC и половинными наградами.
4. Включите **View → Output**. Ожидается строка `Cursed Survival 0.1.0-alpha server ready; persistence: MEMORY`. Ошибки загрузки R15 или API нужно исправить до публикации.
5. Для PvP используйте инструменты **Server & Clients** в Studio, сначала с 2, затем с 3–4 клиентами. Не публикуйте игру как готовую до тестов из `docs/QA.md`.

## Управление

- WASD — движение; Shift — спринт; ЛКМ — удар; X — тяжёлый удар.
- Q, E, R, F — техники; **T — пятая техника главного героя**; G — ультимейт.
- **Y удерживать 4 секунды — печать**. Отдельная клавиша предотвращает конфликт с техникой E. Энергию подбирают обычным ProximityPrompt.
- Телефон: стандартный джойстик, наведение центром камеры, кнопки техник и переключатель БЕГ. Нажатие и удержание экранной подсказки активирует печать.
- МЕНЮ: магазин, коллекция, статистика, задания, ежедневный бонус, приглашения, настройки и отключённые ненастроенные товары Robux.
- Наблюдение после смерти: кнопка «НАБЛЮДАТЬ →» переключает живых участников.

## Что есть

- Серверный автомат всех 10 состояний, таймеры 240 / 20 / 10 секунд, восстановление после исключений и защита переходов.
- Hunt, Clash, Invasion, Survival, Betrayal; минимальные составы; скрытый носитель превращается через 60 секунд. В Clash создаётся центральная арена; счёт побед сервера доступен в статистике.
- Взвешенные роли с RolePity, 650 HP у Астры/Годжо, 850 у Рэна/Сукуны, 100 у мага. Маг получает две совместимые техники и кулаки либо катану.
- 12 техник главных героев, 12 техник магов, базовый и тяжёлый удары. Серверные ресурсы, попадания, line of sight, cooldown, заряд ультимейта, stun, heal, shield, knockback, summon, traps и domains.
- Три карты: SHIBUYA CITY, SORCERER ACADEMY, CURSED DISTRICT. Геометрия, интерьерные проходы, лестницы на крыши, укрытия, печати, энергия и три класса разрушаемых элементов.
- Weak/Fast/Elite NPC, босс Survival, процедурная теневая собака; максимум 18 NPC и ограничение вычисления путей. Весь NPC-код выполняется сервером.
- Создаваемые Roblox API R15-риги, оригинальные процедурные волосы/аксессуары, локомоция и боевые позы через Motor6D. Опубликованные AnimationId не требуются для текущей реализации.
- HUD, мобильные кнопки, роль, результаты, магазин за монеты, коллекция, задания, настройки и диагностика количества NPC/эффектов.
- Монеты, XP/уровни, статистика, ежедневные/недельные задания, ежедневный бонус, ауры, сохранение через UpdateAsync и lease сессии. Studio всегда использует память и не трогает production DataStore.
- Единственный ProcessReceipt; выдача продукта и запись receipt сохраняются в одном объекте данных. Неизвестные продукты откладываются. Все Product/Pass ID по умолчанию 0 / NOT_CONFIGURED.

## Обязательные действия владельца

1. Откройте и протестируйте файл в Studio. Этот шаг ещё НЕ ВЫПОЛНЕН. Оформление карты, физика, responsive UI, spawn и реальные API должны пройти визуальную и игровую проверку.
2. Сохраните собственный `.rbxl`, затем опубликуйте отдельное закрытое тестовое experience. Установите лимит сервера **15**, режим аватара **R15**. Не включайте StreamingEnabled до отдельной проверки.
3. Проверьте реальную запись и повторный вход через опубликованный приватный сервер. В Studio сохранения намеренно выключены независимо от API Services. При отказе загрузки данных игрок не допускается в игру; при неоднозначной ошибке записи сессия закрывается, чтобы не затереть покупку старой копией. Неподтверждённый прогресс после последнего успешного сохранения может быть потерян.
4. Загрузите принадлежащие вам `assets/Audio/*.wav` через Asset Manager и разрешите их использование experience. В `ReplicatedStorage.Shared.Config.Sounds` укажите реальные строки `rbxassetid://...` для `Basic`, `Heavy`, `Blue`, других техник, `Hit`, `Scare`, `Domain` и `Burst`. До этого звук в игре отсутствует. WAV созданы синтезом, внешняя музыка не использовалась.
5. При необходимости замените процедурные позы авторскими анимациями: Idle, Walk, Run, Jump, Fall, Basic, Heavy, Ability, Ultimate, Hit, Death. **Ни одна заказная анимация ещё не загружена и не опубликована.** Текущие движения и короткие позы являются функциональным локальным вариантом; сложная анимационная постановка не готова.
6. Для Robux-магазина создайте реальные продукты/пропуски, внесите ID в Config, для продуктов обновите Status. Проверьте ownership и receipt в закрытом experience. В Studio реальные промпты покупок отключены. Не включайте продажу до проверки DataStore/receipt.
7. По умолчанию `UseOriginalNames=true`: Астра и Рэн. Имена Годжо и Сукуна доступны при `false`; художественные модели и звуки оригинальные. Правовую возможность использования названия JUJUTSU и имён решает владелец перед публичным релизом.
8. Пройдите все NOT RUN строки `docs/QA.md`, включая мобильный экран, высокий ping и десять раундов. Измерьте производительность на целевых устройствах; 60/30 FPS не гарантированы.

## Исходники и сборка

- `src/Shared` — баланс, определения и утилиты.
- `src/Server/Services` — серверные сервисы; `src/Server/Bootstrap.server.lua` — единственная точка запуска сервера.
- `src/Client` — клиентские контроллеры; UI создаётся в PlayerGui при запуске.
- `assets/Maps/*.rbxmx`, `assets/Lobby.rbxmx` — сгенерированные модели.
- `tools/build.mjs` — генератор геометрии и готового `.rbxlx`, без сторонних npm-зависимостей.
- `default.project.json` — альтернативный импорт через Rojo. Команда `rojo build default.project.json -o game.rbxlx` создаёт проект из исходников и моделей; используется при установленном Rojo. Рекомендуемый первый запуск — приложенный `.rbxlx`.

При изменении исходников на диске выполните из корня проекта:

```powershell
node tools/build.mjs
node tools/test-bundle.mjs
luau tests/core.spec.lua
luau tests/boundaries.generated.lua
```

`luau` и `luau-compile` — официальные CLI Luau. Для автоматической проверки есть `tools/verify.ps1`; путь к папке CLI передаётся параметром `-LuauDirectory`. Скомпилированные Roblox API-зависимости не проверяются обычным CLI как engine-типы: нужны Script Analysis и запуск Studio. Не сохраняйте изменения из открытой старой копии Studio поверх новой сборки.

Подробное состояние этапов: `docs/IMPLEMENTATION.md`. Проверки и оставшаяся приёмка: `docs/QA.md`. Архитектура и ограничения: `docs/ARCHITECTURE.md`.
